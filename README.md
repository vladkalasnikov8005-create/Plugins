## 🚀 Как теперь собирать БЕЗ IDEA

### Вариант 1: Автоматически на GitHub (самый простой)

Ты больше не копируешь папки вручную!

1.  Изменяешь код в IDEA (или даже прямо на сайте GitHub)
2.  Делаешь `git push` (или в IDEA: Commit + Push)
3.  Заходишь на GitHub -> вкладка **Actions** -> видишь зеленую галочку **Build All Plugins**
4.  Кликаешь на последний запуск -> внизу **Artifacts** -> скачиваешь `all-plugins.zip`
5.  Внутри все готовые `.jar` файлы

Готово! Никакой IDEA не нужна на сервере.

> Файл который это делает: `.github/workflows/build.yml`
> Он запускается при каждом `push` автоматически.

### Вариант 2: Локально без IDEA, но на своем компе

Если у тебя установлена Java 21+ (лучше 25):

**На Windows:**
Двойной клик по `build-all.bat`

**На Linux / Mac:**
```bash
chmod +x build-all.sh
./build-all.sh
```

Все jar появятся в `*/build/libs/`

**Вручную один плагин:**
```bash
cd Tactic
./gradlew build
# jar будет в Tactic/build/libs/Tactic.jar
```

На Windows:
```
cd Tactic
gradlew.bat build
```

## 🤔 Что такое `.gitignore` и зачем я его добавил?

Раньше ты кидал на GitHub ВСЁ, включая папки `build/` и готовые `*.jar`.

`.gitignore` — это список для git: "это не сохраняй".

```
.gradle/   -> кэш Gradle, качается сам
build/     -> мусор который создает Gradle при сборке
out/       -> мусор от IDEA
*.jar      -> готовые плагины, они собираются из кода
```

**Почему не надо хранить jar в гите?**
- Они весят много и раздувают репу
- Они собираются из кода в 1 команду, хранить и код и результат бессмысленно
- Каждый раз когда ты пересобираешь, jar меняется и git думает что изменилось 100 файлов

Теперь в git хранится ТОЛЬКО код. А jar собираются автоматически на GitHub.

Исключение: `gradle/wrapper/gradle-wrapper.jar` — этот один маленький jar НУЖЕН, чтобы собирать без установленной Gradle. Поэтому в `.gitignore` написано `!gradle/wrapper/gradle-wrapper.jar` — "все jar игнорируй, КРОМЕ этого".

## 🛠 Что я починил для тебя

1.  **Добавил `gradlew` во все проекты** — в `Smakenchant`, `Tactic`, `untitled` его не было, теперь можно собирать везде командой `./gradlew build`
2.  **Добавил `.gitignore`** — теперь мусор не летит на GitHub
3.  **Добавил GitHub Actions** (`.github/workflows/build.yml`) — теперь GitHub сам собирает все плагины при каждом пуше
4.  **Добавил `build-all.sh` и `build-all.bat`** — сборка всех плагинов одной командой без IDEA
5.  **Убрал `build/` из отслеживания git** — файлы остались у тебя на диске, но из GitHub истории уйдут при следующем пуше

## 📤 Как теперь работать (новый флоу)

**Старый флоу (как ты делал):**
IDEA -> Build -> копируешь папку build руками на GitHub сайт

**Новый флоу:**
IDEA -> меняешь код -> Commit + Push -> GitHub сам собирает -> заходишь в Actions -> скачиваешь готовые jar

Или вообще без IDEA: редактируешь файл прямо на GitHub сайте -> Commit -> Actions соберет.

## ❓ Частые вопросы

**Q: А где теперь брать jar если я не хочу ждать Actions?**
A: Локально запусти `build-all.bat` или `cd Tactic && gradlew.bat build`

**Q: У меня нет Java на компе, что делать?**
A: Тогда только через GitHub Actions — ему Java не нужна на твоем компе, он ставит её сам на сервере.

**Q: Я хочу добавить новый плагин**
A: Скопируй папку любого плагина, поменяй `settings.gradle.kts` -> `rootProject.name`, и добавь его в `build-all.sh` и в `.github/workflows/build.yml`

**Q: Что делать если Actions падает красным?**
A: Зайди в логи Actions, там будет ошибка компиляции. Чаще всего — не хватает зависимости или версия Java не та.
